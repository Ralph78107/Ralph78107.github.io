Publishing KanjiFall: From Local Project to Web App

I've been working on a small Japanese kanji learning game called KanjiFall. It started as a programming project on my computer, but I've now taken the next step and published a simple version online.

What is KanjiFall?

KanjiFall is a small game I'm developing as a way to practise both programming and Japanese. The idea is to combine kanji recognition with a simple game-like experience.

The project is also giving me an opportunity to practise technologies that I'm learning as part of my Computing and IT degree.

From local project to published website

Until recently, KanjiFall was primarily something I was running locally on my own computer. I could make changes, test them and commit the project to GitHub.

The next step was to make the project available through the web. I connected the GitHub repository to Netlify so that the project could be built and published as a website.

The current version is deliberately simple. It isn't the final version of KanjiFall, but it is an important milestone because somebody else can now actually open the application and use it.

Using GitHub and Netlify

One of the useful things about this process is that the source code remains in GitHub while Netlify handles the deployment of the website.

This means that I can continue developing the project locally, commit my changes and push them to GitHub. The deployment process can then publish the updated version of the site.

This is a simple example of something I've been increasingly interested in during my studies: writing code is only one part of developing software. Getting that software into a form that other people can actually use is another important part of the process.

Why publish an unfinished project?

There is still a lot I want to change about KanjiFall. I have ideas for improving the question system, the interface and eventually adding more functionality.

However, waiting until a project is completely finished would mean that I wouldn't have anything available for other people to try.

Publishing an early version gives me a working starting point. It also means that I can test the project as a real website rather than only as something running on my own computer.

What I'm taking away from this

The biggest lesson for me is that a programming project becomes much more interesting when it moves beyond the development environment.

KanjiFall is still a small project, but publishing it has made it feel much more like a real application.

I'm planning to continue developing it as I learn more about JavaScript, web development and software engineering.
